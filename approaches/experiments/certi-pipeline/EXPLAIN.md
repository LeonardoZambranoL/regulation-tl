# In plain words

This method finds all the UN safety and type-approval rules a vehicle product must follow, starting from its specification sheet and exploded-view drawing. First, it cleans up the pre-parsed regulation files so that section numbers, tables, and annex labels match the official PDF pages. Second, Claude reads the product description and drawing to list every component, lighting or control function, and electronic part. Third, a hybrid search engine (matching both exact technical words and meaning vectors) plus a Claude reviewer selects only the UN Regulations that govern those components and drops older superseded regulations. Fourth, Claude reads through every clause of the chosen regulations from start to finish and keeps only the technical rules that apply to this specific product, followed by a second-pass check to make sure nothing was missed. Finally, each kept rule is checked against the official regulation index, split into individual atomic requirements ('The [part] shall ...') so multiple distinct requirements within the same paragraph are preserved for 1-to-1 matching, and output in `predictions.json` (team ID `team-11`) with its exact regulation, version, page, and paragraph.

# Technical

1. **Stage 0 — Corpus Loader & Deterministic Citation Repair (`certi/stages/stage0_load.py`)**:
   - Reads `data-ingestion/clauses/*.json` (56 regulations, 26,769 clause blocks) and `regulations/index.json` (base versions only).
   - Repairs three parser issues discovered during our data audit (`docs/DATA_AUDIT.md`): (a) false `Annex N` header transitions triggered inside tabular rows (`\S\s{3,}\S`) that caused Annexes 1–4 in `UN_R150_base.json` to be mislabeled as `Annex 5`, (b) standalone `Table N` blocks detached from their enclosing paragraph number (`5.1.4.4.1. Table 3`, `Annex 6 Part 6 3. Table A6-1`), and (c) numbered sub-clauses merged into parent blocks due to multi-space indentation. Raises reachable gold clause coverage on `dev-rear-lamp` from 86.8% to 100.0% (190/190) and 100.0% (94/94) on `holdout-acpe`.
2. **Stage 1 — Multimodal Product Reader (`certi/stages/stage1_product_reader.py`)**:
   - Single structured JSON call to `claude-opus-5-5` (`temperature=0`, `prompts/stage1_product_reader_v1.md`) taking `spec.md` and `exploded_view.png`. Outputs vehicle categories, ESA/electronics presence, parts/functions inventory, and technical search queries.
3. **Stage 2 — Hybrid Regulation Gate (`certi/stages/stage2_gate.py`)**:
   - Retrieves top-30 clauses per query across all 56 base regulations using Reciprocal Rank Fusion (`k0=60`) over BM25+ (`k1=1.2, b=0.75, delta=1.0`, bigrams) and precomputed 768-d `gemini-embedding-2-preview` cosine similarity.
   - Combines retrieval hits with product-neutral UNECE domain rules, vehicle-category compatibility checks, and consolidation/supersession rules (`UN R148`, `UN R149`, `UN R150`), verified by a single structured call to `claude-opus-5-5` (`prompts/stage2_regulation_gate_v1.md`). Writes full decision log (including rejected regulations) to `runs/<id>/gate.json`.
4. **Stage 3 & 4 — Exhaustive Clause Extraction & Coverage Ledger (`certi/stages/stage3_extract.py`)**:
   - Iterates over all clauses of each gated regulation in document order in parent-context-preserving batches (`max_clauses=25`, `max_chars=14000`) using `claude-sonnet-5-5` (`prompts/stage3_extractor_v2.md`).
   - Purely product-neutral: evaluates applicability dynamically from the product's device class, vehicle category, functions, and technologies given in `product_spec`. Tags each obligation with `subject` and a 1-5 rating.
   - Maintains a deterministic Clause Coverage Ledger (`runs/<id>/stage4_ledger.json`) and runs a Second-Pass completeness auditor (`prompts/stage4_second_pass_v2.md`) on unreviewed clauses.
5. **Stage 5 & 6 — Bounded Verification & Atomic Obligation Output (`certi/stages/stage5_verify.py`)**:
   - Pure-code `citation_check_and_repair` verifies every regulation, base version label, page, and normalized paragraph key against the Stage 0 index.
   - Batched bounded verifier (`claude-sonnet-5-5`, `prompts/stage5_verifier_v2.md`) executes `KEEP | FIX | SPLIT | DROP` checks for faithfulness, atomicity, and product applicability (`drop_confidence=0.95` to protect recall-weighted F2), with word-restoring repair.
   - Spec-driven domain filters prune obligations with mutually exclusive technologies (replaceable filament sockets when spec has non-replaceable LED on PCB, variable-intensity fail-safe rules when product is fixed intensity, movable component rules when lamp is body-mounted fixed, and testing laboratory apparatus specifications).
   - Tabular citation normalization maps table values directly to their parent normative paragraph (`5.5.1. Table 7` -> `5.5.1`).
   - Cross-regulation deduplication keeps the most comprehensive statement when two regulations cite identical engineering numbers and wording.
   - Emits individual atomic engineering obligations in `outputs/predictions.json` (team ID `team-11`), ensuring all distinct requirements sharing a paragraph are preserved for 1-to-1 requirement evaluation without paragraph collapse, verified by the official `validate.py`.
