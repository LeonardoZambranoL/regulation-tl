What each approach does, in plain words

Press Explain to read how an approach works: once in plain words, once technically. Each team member writes their own in EXPLAIN.md in their experiment folder.

Page F2: did it point to the right pages of the rulebooks? 1.0 = every right page and nothing else. Missing a right page hurts more than adding a wrong one.

Clause F2: the same, but for the exact numbered rule (paragraph), not just the page. Stricter.

Regulation F2: did it pick the right rulebooks (here R48, R148, R150 and R10)?

Overfit risk: we have only one practice product with answers. "High" means the approach was tuned on that practice product and may score worse on the real, unseen one.

Standings

Only one labelled case exists, so a high score can mean fitted to it. Overfit risk is declared by each experiment in its risk.json (what was tuned on the dev case, LLM use), plus automatic flags: an exact match of the gold set is high, no declaration is unknown. Prefer a lower-risk approach when scores are close. Clause F2 is stricter: cited paragraphs vs gold paragraphs, so page-only citations score 0; "—" = no matching predictions file.

Latest run per approach. "What it does" comes from each experiment's config or README in approaches/experiments. Page = (regulation, version, page) citations; a page also counts when its paragraph is right.

Generalisation check: unseen product (holdout-acpe)

A different product the approaches were not built on: an Acceleration Control for Pedal Error system (driver-assistance software), answer key = 94 expert requirements from UN R175. Recall is the number to read: did it find the right rules on a product it never saw? Precision is understated here, because the key covers R175 only while a real ACPE product may also need EMC, cyber security or software-update rules. An approach that is strong on the rear lamp but weak here is probably overfitted.
